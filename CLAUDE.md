Instructions for Claude Code working in this repository. Read fully before any change.

## Project in one paragraph
SensoryRec is an IE University BDBA capstone. It is a **content-based** wine recommender: a novice describes what they like in everyday words, and the system retrieves matching wines from the Wine Enthusiast Reviews dataset (Kaggle, ~129,971 rows) by comparing the query with professional tasting notes using Sentence-BERT. Results are delivered through a **RAG chatbot**: retrieval ranks the wines, an LLM only writes an explanation grounded in the retrieved notes. The research focus is **cold start under data sparsity** and **long-tail exposure**.

## Frozen scope (do not expand without the student's explicit approval)
IN: data pipeline, EDA, Popularity / TF-IDF / Attribute / SBERT recommenders, plain-language refinement, offline evaluation, RAG chat UI.
REQUIRED: one complete worked example in the demo (persona → query → top-5 with bottle images → refinement → grounded explanation).
INCREMENTS (only after core is done, in this order): A) bottle images for a curated demo subset + generic fallback; B) group mode for two friends; C) restaurant wine-list photo → OCR → rank menu wines (stretch).
OUT: collaborative filtering, context-aware recommendation, location/availability and maps (Future Work; at most a clearly labelled mock-up), external purchase APIs, spirits, fine-tuning models.
NEVER scrape sites whose Terms of Service forbid it (e.g. Vivino, Google). Every external image must have its source and licence logged in `data/images/sources.csv`.
If a task seems to need something in OUT, stop and ask.

## Non-negotiable rules
1. **Reproducibility.** Every result in the thesis must be regenerated by a command. Fixed seeds (`SEED=42` in `config.yaml`). Pin package versions in `requirements.txt`. No manual steps in notebooks that the pipeline depends on.
2. **The LLM never ranks.** Ranking = deterministic scores only. The LLM is used for (a) explanation text and (b) optionally generating casual test queries. All LLM outputs are cached to `data/llm_cache/` (JSON, keyed by prompt hash) and committed, temperature 0, model name pinned in config.
3. **No fabricated numbers.** Never write metric values into docs or README by hand; they come from `results/*.csv` produced by scripts. If a result is missing, say so.
4. **Evaluation split.** Test notes (~200) are held out before any fitting (TF-IDF vocabulary, popularity counts, attribute stats, direction vectors). No leakage.
5. **Casual queries** must not contain expert tasting vocabulary. Check them against `data/wine_vocab.txt`; log violations.
6. Keep code simple and readable; a student must be able to explain every function in an oral defence.
